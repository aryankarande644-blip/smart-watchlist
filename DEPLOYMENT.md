# Deployment Runbook — Smart Market Watchlist (Phase 1: demo mode)

Topology: **Render** hosts the backend + Postgres. **Vercel** hosts the React
frontend (static build). Phase 1 runs `MARKET_DATA_PROVIDER=demo` so the
deployment plumbing is proven with zero external variables; Phase 2 flips one
env var to `real` (see HANDOFF Section 10 #3).

Ownership: these are the exact commands/configs to run. The repo is already
`git init`-ed and committed locally as `main`; you create the remotes.

---

## 0. Prereqs
- A local git binary with your identity configured is enough — no platform
  CLI is required for this git-based flow. (Full CLI instructions are given
  only for verification, e.g. `curl` for health checks.)
- The repo root is `/home/aryan/smart_watchlist`, already committed on `main`.

## 1. Push the repo up
Create a private GitHub repo (e.g. `smart-watchlist`), then:

```bash
cd /home/aryan/smart_watchlist
git remote add origin git@github.com:<you>/smart-watchlist.git
git push -u origin main
```

## 2. Backend on Render (two passes for URL wiring)

**2a. Create Postgres**
- Render dashboard: New + Postgres. Free instance is fine.
- Copy its **Internal Database URL** (stays inside Render's network), for 2d.

**2b. Import blueprint**
- Render dashboard: New + Blueprint, pick the repo.
- It creates the `watchlist-backend` web service from `render.yaml`
  (rootDir `backend`, health check `/health`, 1 instance).

**2c. Fix env vars before the first deploy** (Service -> Environment)
- `DATABASE_URL` <- the Internal Database URL from 2a (ignore the render.yaml
  placeholder).
- `FRONTEND_ORIGIN` <- left as the placeholder for now (Vercel URL not known
  yet; see step 4 for the flip).
- `SESSION_SECRET` <- auto-generated by the blueprint (`generateValue`). If you
  change it later, all sessions invalidate — fine here.
- `NODE_ENV=production`, `MARKET_DATA_PROVIDER=demo`, `SESSION_COOKIE_SAMESITE=none`
  are already set by the blueprint. Leave them.
- Trigger a manual deploy (Deploy button) after editing env vars.

**2d. Verify the backend in isolation (curl, no Origin header — passes CSRF):**

```bash
curl -s https://<service>.onrender.com/health
# {"status":"ok","db":"ok","poller":{...},"marketDataCircuit":"closed"}
curl -s -X POST https://<service>.onrender.com/watchlist \
  -H 'Content-Type: application/json' -d '{"symbol":"TCS"}'
# any symbol 201s in demo mode (by design — see HANDOFF caveat)
```

Keep the Render URL; you need it for the frontend env.

## 3. Frontend on Vercel
- Import the same GitHub repo; **Root Directory = `frontend`** (vercel.json
  sets build/output; auto-detects Vite).
- Project -> Settings -> Environment Variables, add (build-time):
  `VITE_API_BASE_URL = https://<service>.onrender.com`
- Deploy. Copy the app URL, e.g. `https://smart-watchlist.vercel.app`.

## 4. Close the wiring loop (the chicken-and-egg)
- Back on Render -> Environment: set `FRONTEND_ORIGIN` to the Vercel URL from
  step 3, exactly (`https://smart-watchlist.vercel.app` — scheme matters).
- Redeploy the Render service once.

## 5. Phase 1 acceptance
```bash
curl -s https://<service>.onrender.com/health            # db ok, circuit closed
curl -s https://smart-watchlist.vercel.app/              # 200, Watchlist app
# In a browser: add TCS + RELIANCE -> live rows appear and move,
# reload keeps the same rows (session cookie survives round-trip).
```
- External keep-alive: point a free uptime monitor (UptimeRobot) at
  `https://<service>.onrender.com/health` every 5 min so the free Render
  instance doesn't sleep.

## Phase 2 (only after acceptance)
- Render -> Environment: `MARKET_DATA_PROVIDER=real`, redeploy.
- Verify in the browser: add a bogus symbol -> `422 unknown_symbol`; add TCS ->
  immediate real snapshot. Note `.nvmrc` pins Node 22 (yahoo-finance2
  requirement); the demo phase never loads that library, which is why Node 22
  only becomes load-bearing for this second phase.

## Env var cheat-sheet

| Var (Render)             | Phase 1 | Phase 2  | Notes |
|--------------------------|---------|----------|-------|
| `MARKET_DATA_PROVIDER`   | `demo`  | `real`   | chosen at boot; flip + redeploy |
| `DATABASE_URL`           | Render Postgres Internal URL | same | |
| `FRONTEND_ORIGIN`        | Vercel URL | same | exact match, scheme matters |
| `SESSION_SECRET`         | generated | same | keep stable post-launch |
| `SESSION_COOKIE_SAMESITE`| `none`   | `none`   | cross-site cookie; origin-check keeps it safe |

|--------------------------|-------|
